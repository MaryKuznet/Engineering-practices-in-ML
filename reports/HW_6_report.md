В рамках домашнего задания была реализована полноценная система документации и автоматической генерации отчётов для ML-проекта. Основной упор сделан на автоматизацию и воспроизводимость результатов.

---

## 1. Документация проекта

Документация создана с использованием **MkDocs**.

### Конфигурация документации
- `mkdocs.yml` — основной конфигурационный файл MkDocs
- `docs/` — директория с исходниками документации

### Структура документации
```
docs/
├─ index.md                 # главная страница документации
├─ usage.md                 # использование проекта
├─ deployment.md            # инструкция по развёртыванию
├─ reproducibility.md       # воспроизводимость
└─ experiments/
   ├─ overview.md           # описание экспериментов
   └─ latest.md             # последний отчёт (генерируется автоматически)
```

Документация собирается в статический сайт с помощью команды:

```bash
mkdocs build --strict
```

Использование флага `--strict` гарантирует, что сборка завершится ошибкой при наличии битых ссылок или отсутствующих файлов.

---

## 2. Публикация документации на GitHub Pages

Для автоматической публикации документации настроен workflow GitHub Actions:

- `.github/workflows/docs.yml`

Workflow выполняет:
1. установку окружения через Pixi  
2. сборку документации (`mkdocs build --strict`)  
3. публикацию сайта в ветку `gh-pages` (`mkdocs gh-deploy`)  

В настройках репозитория GitHub Pages используется:
- ветка: `gh-pages`
- каталог: `/ (root)`

Документация автоматически обновляется при изменениях в репозитории и доступна в виде сайтаЖ
https://marykuznet.github.io/Engineering-practices-in-ML/

## 3. Отчёты об экспериментах

Для формирования отчётов реализован отдельный скрипт:

- `src/reports/build_report.py`

### Источники данных
- `reports/train_reports/train_info.json` — информация о запуске обучения
- (опционально) `reports/experiments.csv` — накопленные результаты экспериментов

### Генерируемые файлы
После выполнения команды:

```bash
pixi run report
```

создаются или обновляются:
- `reports/experiments.md` — полный отчёт об экспериментах в формате Markdown
- `docs/experiments/latest.md` — последний отчёт, отображаемый на сайте документации
- `reports/figures/` — графики и визуализации метрик (при наличии)

Отчёты содержат таблицы с параметрами запуска и результатами, а также графики метрик.

## 4. Воспроизводимость

Для обеспечения воспроизводимости проекта используются Pixi и DVC.

### Основные команды
- установка окружения:
```bash
pixi install
```

- загрузка данных:
```bash
pixi run dvc pull
```

- обучение модели:
```bash
pixi run train
```

- генерация отчётов:
```bash
pixi run report
```

### Полный воспроизводимый сценарий
Реализована единая команда:

```bash
pixi run repro
```

Она автоматически выполняет:
1. загрузку данных  
2. обучение и оценку модели  
3. генерацию отчётов  
4. сборку документации
